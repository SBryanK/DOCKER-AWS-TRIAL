How it works

Four steps from PDF to cited answer.

Ingest

pypdf extracts text page by page. Chunks are sentence-aligned with overlap and stable ids, so citations never start mid-word.

Embed

Each chunk becomes a 1024-dim vector. Bedrock: Titan or Cohere. Offline: deterministic feature hashing — lexical, transparent, and free.

Retrieve

Vector similarity proposes candidates; BM25 re-ranks them. Hybrid retrieval catches exact identifiers that small embeddings miss.

Answer

The model only sees retrieved passages and must cite them as [n]. If the corpus does not cover the question, the API says so instead of guessing.

Docker engineering

1.83 GB → 429 MB, with receipts.

Multi-stage build, slim base, non-root user, healthcheck, pinned lock file. The naive image is committed too, so the comparison is reproducible.

Image size

naive:python3.13
1.83 GB
production
429 MB

−77% size, same API. The runtime stage only receives a pre-built venv and app/; build tools stay in the builder stage.

Build cache behaviour

  • no-change rebuild: 1.79 s
  • app-code change: 0.78 s
  • dependency change: 10.65 s

Dependencies are copied before app code, so day-to-day edits skip the expensive install layer.

Security

No keys, no root

Secrets excluded from git and image; AWS profile mounted read-only at runtime only; app runs as uid 10001 with upload size/type limits.

Persistence

Volumes that prove it

After restart and down/up, the API still reports 719 chunks and Qdrant still holds 719 points. down -v deletes them.

Ops

Health-gated startup

Docker healthcheck plus depends_on: service_healthy: the API never starts before Qdrant is ready.

Quickstart

Reviewer demo in one command.

No AWS account needed for the offline path. Bedrock mode is one env switch away.

Offline · Docker Compose
# clone + start API and Qdrant
git clone https://github.com/SBryanK/DOCKER-AWS-TRIAL.git
cd DOCKER-AWS-TRIAL
docker compose up --build -d

# index the bundled corpus (205 pages)
curl -X POST http://localhost:8000/ingest/sample

# ask with citations
curl -X POST http://localhost:8000/ask \
  -H 'Content-Type: application/json' \
  -d '{"question":"What are the four core functions of the NIST AI RMF?"}'

# open the UI
open http://localhost:8000

Cloud notes

AWS facts, verified and flagged.

Region-specific model availability, pricing citations and the one EOL trap that would have broken a copy-pasted tutorial.

Generator

Nova Lite, APAC profile

apac.amazon.nova-lite-v1:0 is confirmed for Converse from Singapore via cross-region inference. Data can route to Tokyo/Seoul/Osaka/Mumbai/Sydney — a residency caveat for policy workloads.

Embeddings

Titan vs Cohere

The Singapore price list publishes Titan V2, but the model card's regional table does not. The repo verifies at runtime and supports cohere.embed-multilingual-v3 as an in-region fallback.

Lifecycle trap

Claude 3 Haiku is EOL

Claude 3 Haiku reached end-of-life in ap-southeast-1 on 2026-11-13. Any blog post still using that ID fails with ResourceNotFoundException — verify IDs instead of trusting tutorials.

Engineering judgement

What I would change at enterprise scale.

Deliberate demo trade-offs

  • Character-based chunks instead of token/section-aware chunking
  • numpy brute-force index locally; BM25 over the whole corpus for offline retrieval
  • Single API process with synchronous ingestion
  • No auth, rate limiting or WAF
  • Logs only; no distributed tracing

Production path

  • Managed vector store + dedicated lexical index + cross-encoder reranker
  • S3-triggered async ingestion with idempotent re-indexing
  • API Gateway / Cognito, quotas, Guardrails, PII redaction before embedding
  • ECS Fargate or EKS with IaC, blue/green deploys, OpenTelemetry
  • Retrieval evaluation in CI against a growing golden set
